# 代码审查弹窗

[产品需求索引](../../PRD.md)

## 1. 代码审查区

保留可复用的 diff 弹窗，包含顶部审查工具栏、代码差异和右侧文件目录树。弹窗关闭时不读取项目 diff，未来由任务或项目入口提供审查上下文。当前主界面不新增审查入口，不再通过点击旧会话进入审查区。

## 2. 对比方式

代码审查功能主要通过 Git 实现，支持以下对比方式。

### 2.1 未暂存

展示当前分支未暂存文件与原文件之间的差异。

对应 Git 语义：

- 通过 Electron main process 在目标项目中实时执行 `git diff`。
- 适合检查尚未加入暂存区的即时改动。
- 不依赖 Agent hooks，不写入本地事件日志，也不生成 patch 快照。
- 首版遵循 Git 原生命令语义，未跟踪文件可在文件状态中提示；如需展示未跟踪文件内容，后续再通过临时 index 补充。

### 2.2 已暂存

展示当前分支已暂存文件与原文件之间的差异。

对应 Git 语义：

- 通过 Electron main process 在目标项目中实时执行 `git diff --cached`。
- 适合提交前确认 staged 改动。
- 不依赖 Agent hooks，不写入本地事件日志，也不生成 patch 快照。
- 如果同一文件在暂存后又继续修改，本模式只展示已暂存版本，未暂存模式展示后续工作区修改。

### 2.3 分支

展示当前分支相对目标分支的全部改动。

对应 Git 语义：

- 默认目标分支为 `main` 或 `master`。
- 如果项目同时存在 `main` 和 `master`，优先使用当前仓库默认远端 HEAD 指向的分支。
- 用户可以点击目标分支并选择其他本地或远端分支。
- 首版通过 Electron main process 实时执行 `git diff <targetBranch>...HEAD`，展示当前分支相对目标分支已经提交的改动。
- 不依赖 Agent hooks，不写入本地事件日志，也不生成 patch 快照。
- 本模式默认不包含未提交的工作区改动；用户可切换到未暂存或已暂存模式分别查看。

### 2.4 对比边界

只支持未暂存、已暂存、分支三种实时 Git 对比，不再提供上轮对话审查。默认使用未暂存；旧设置中的已移除模式回退为未暂存，不读取历史 patch。

## 3. 审查区顶部通栏

审查区顶部通栏分为两行。

### 3.1 第一行

左侧展示：

- 当前对比方式。
- 对比方式下拉菜单。
- 代码新增行数。
- 代码删除行数。
- 未暂存/已暂存模式的非零文件数量角标。

右侧展示：

- 查看选项 icon。
- 刷新 icon。
- 差异视图切换 icon。
- 提交或推送按钮组。

查看选项点击后展开下拉菜单，包含：

- 开启/禁用差异换行。
- 折叠/展开全部差异。

刷新 icon 点击后重新读取当前 Git 状态并刷新 diff。

差异视图切换 icon 控制 diff 视图：

- 统一视图：同一个代码块中展示增删差异。
- 分栏视图：左右两列分别展示变更前和变更后代码。

提交或推送按钮组根据仓库状态提供操作：

- 存在已暂存或未暂存改动时，弹窗展示提交信息、是否包含未暂存改动和对应增删统计；填写提交信息后可选择提交或提交并推送；若同时存在未推送提交，推送操作也保持可用。
- 仅存在已提交但未推送的提交时，主按钮作为快捷操作直接执行推送；下拉入口仍可打开操作弹窗，弹窗不展示提交信息输入区且仅允许推送。
- 没有可提交或可推送内容时，操作入口禁用。
- 取消“包含未暂存的更改”后，若没有已暂存改动，仅允许普通提交；若存在已暂存改动，提交和提交并推送均可用。前一种状态下普通提交会将本地改动纳入提交，但不会自动推送。
- 当前分支没有 upstream 但已经存在本地提交时，仍视为存在可推送内容，并通过首次推送自动建立 upstream。
- 提交弹窗支持键盘操作：macOS 使用 `⌘↩`，Windows/Linux 使用 `Ctrl+Enter` 执行当前高亮动作；输入框聚焦时可用上下方向键切换可用动作。

### 3.2 第二行

展示：

- 当前分支名，不可编辑。
- 目标对比分支名，可点击选择。

当当前对比方式不是“分支”时，目标分支信息可以置灰展示，避免误导。

## 4. Diff 展示

Diff 区域位于审查区主体左侧，是主要阅读区域。

### 4.1 基础展示

1. 按文件顺序展示全部 diff。
2. 每个文件展示文件路径、文件状态和增删统计。
3. 文件状态包括新增、修改、删除、重命名。
4. 代码风格接近 GitHub diff。
5. 支持 light 和 dark 主题。

### 4.2 滚动与定位

1. Diff 区域支持纵向滚动。
2. 用户点击文件树节点后，diff 区域滚动到对应文件。
3. 当前正在阅读的文件应在文件树中高亮。

### 4.3 折叠

1. 用户可以折叠或展开单个文件 diff。
2. 用户可以通过查看选项统一折叠或展开全部文件 diff。
3. 折叠后仍展示文件名、文件状态和增删统计。

### 4.4 长行处理

用户可以开启或禁用差异换行。

- 开启换行：长行在可视区域内自动换行，适合阅读文本和配置文件。
- 禁用换行：长行横向滚动，适合阅读代码对齐和格式变化。

### 4.5 阅读模式

1. 连续模式：按文件顺序连续滚动阅读全部 diff。
2. 单文件模式：一次只展示一个文件，通过文件树切换当前文件。
3. 当 diff 总量超过大差异阈值时，自动进入单文件模式并展示提示条。

### 4.6 本地评论

1. 用户可以在 diff 行号处添加本地评论，允许同时打开多个评论框。
2. 评论只保存在本地，统一视图和分栏视图使用一致的行号规则（删除行为 L 侧，新增行和上下文行为 R 侧）。
3. 已保存的评论可导出为通用文本模板，供用户粘贴给 Agent 执行修改。

### 4.7 文件操作

1. 文件头 hover 时展示文件操作：暂存、取消暂存、还原，按当前对比方式展示可用项。
2. 支持批量操作：全部暂存、全部取消暂存、全部还原。
3. 文件支持右键菜单：在 VS Code 中打开、复制路径、复制相对路径。

## 5. 文件目录树

文件目录树位于审查区主体右侧。

### 5.1 展示规则

1. 按目录层级展示本次改动文件。
2. 文件节点展示文件类型图标和文件名。
3. 目录节点只展示目录名，不展示文件数量。
4. 默认展开所有包含改动文件的目录。

### 5.2 交互规则

1. 点击文件节点后，左侧 diff 锚点到对应文件。
2. 当前阅读文件在目录树中高亮。
3. 当文件数量较多时，目录树独立滚动。

## 6. 布局与补充交互

- 弹窗约为窗口宽度的 92%、高度的 88%，使用主题圆角背景；工具栏、diff 与右侧文件树保留。
- 文件头高 36px、吸顶；点击整行折叠/展开，悬停时显示当前模式可用的暂存、取消暂存与还原操作。
- 删除行评论标记 Lxx，新增和上下文行标记 Rxx；统一与分栏模式规则一致，分栏左侧为 L、右侧为 R。
- 大量差异自动进入单文件模式时展示 28px 高提示条：“检测到大量差异：每次仅显示一个文件。”。
- 查看选项收纳差异换行与全部折叠/展开，选择后关闭弹层；统一/分栏使用同一按钮互切，图标表达下一次动作。
- 文件块右键菜单跟随最新右击点定位，提供文件打开、路径复制和换行选项。
- 代码主题默认 Pierre light/dark，行内差异与行号侧颜色条遵循阅读偏好。

### 6.1 文件树布局与操作

文件树是审查区右侧的强导航区域：

- 默认宽度约 360px。
- 左侧边框支持拖拽调整宽度。
- 宽度到 200px 后继续向右拖拽 80px 视为关闭趋势，自动收起文件树。
- 展开/收起文件树需要滑出动画；拖拽调整宽度时不使用动画。
- 顶部筛选框用于按文件路径过滤。
- 目录支持展开收起，目录不展示文件数量。
- 文件支持右键菜单：在 VS Code 中打开、复制路径。
- 文件图标按文件类型适配，整体保持小尺寸和高密度。

文件树背景与 diff 区域保持同色，避免右侧导航显得像独立卡片。

## 7. 目标分支切换流程

1. 用户在审查区选择“分支”对比方式。
2. 用户点击目标分支名。
3. 应用展示可用本地分支和远端分支列表。
4. 用户选择目标分支。
5. 应用重新计算 diff。
6. 顶部通栏更新增删统计和文件数量。

## 8. 异常与性能

### 8.1 非 Git 目录

如果传入 diff 弹窗的项目路径不是 Git 仓库，审查区展示 Git 错误，不影响任务面板、Issue 列表和设置。

### 8.2 Git 命令失败

当 Git 命令执行失败时：

1. 审查区展示错误状态。
2. 显示简短错误原因。
3. 提供刷新按钮。
4. 不影响其他任务与模块状态。

### 8.3 文件过大

当单个文件 diff 过大时：

1. 默认折叠该文件。
2. 展示文件过大的提示。
3. 用户可以手动展开。

具体阈值可先设为单文件 diff 超过 3000 行。

### 8.4 二进制文件

二进制文件不展示代码 diff，只展示文件状态和路径。

### 8.5 删除或移动项目

如果传入 diff 弹窗的项目路径不存在：

1. 审查区展示项目路径不可访问。
2. 不删除已有任务、条目或磁盘中的历史审查记录。
3. 关闭弹窗后仍可使用其他模块。

1. 普通项目中，打开审查区后 1 秒内展示基础结构和加载状态。
2. diff 计算完成后渐进式渲染内容，避免窗口卡死。
3. 大文件和大量文件场景下，目录树与 diff 区域应保持可滚动。

## 9. 验收标准

- 未暂存、已暂存和分支分别与对应 Git 差异一致，没有上轮对话审查；旧模式回退未暂存。
- 弹窗关闭时不读取项目 diff，主页面当前不新增审查入口。
- 顶部统计、刷新、视图切换、换行、全部折叠和文件定位正确。
- 连续与单文件阅读均可用，当前文件与目录树选择同步，大差异保持可滚动。
- 评论行号跨统一/分栏一致，支持多个评论框与文本导出。
- 文件级、批量 Git 操作及提交/推送遵循仓库状态和可用动作规则。
- 非 Git 目录、路径失效、Git 错误、二进制和大文件状态明确且不影响其他页面。
