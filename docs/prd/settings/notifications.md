# 通知

[设置概览](README.md) · [产品需求索引](../../../PRD.md) · [任务工作台](../task-workspace.md)

## 1. 入口与说明

设置分类在常规之后提供「通知」。页面说明桌面通知和应用内提醒的区别：桌面通知在 Navo 处于后台时出现，应用内提醒在使用 Navo 时出现。不提供 Kepler 的外部会话、只通知一次等规则。

## 2. 要通知的内容

同一张分组里列出回复、提问、权限请求、批准请求和错误。每行右侧两列分别是桌面和应用内，用复选框独立开关。列标题为桌面、应用内。

- 回复：Agent 回复结束，轮到你了。默认关闭。
- 提问：Agent 提出问题并等待回答。默认两边都开。当前没有可靠的等待回答信号，开关会保存，但不会从终端文本猜测并发出提醒。
- 权限请求：Agent 需要许可才能继续。默认两边都开。只在已确认的等待权限相位出现时发出。
- 批准请求：Agent 请求一项只有你能批准的操作。默认两边都开。当前没有这类结构化请求，开关会保存；删除 Worktree 等仍走原有确认框，不另发通知。
- 错误：会话因为出错而停止。默认两边都开。

分组底部还有两项：

- 桌面通知时播放提示音，默认开启。只伴随真正发出的桌面通知，应用内提醒不出声。
- 正在查看的任务也通知，默认关闭。关闭时，当前窗口里打开的任务保持安静，包括并排拆分里同时可见的任务。窗口在后台时，这条例外不压制桌面通知。

通知正文只包含会话名称和状态，权限请求可带上工具名。不包含任务正文、终端输出或命令参数。点击桌面通知或应用内提醒都会打开对应任务。应用内提醒出现在窗口右上角，可点关闭或向右滑掉，不自动消失，不影响未读标记。应用刚启动时已有的回复和失败不补发。

旧版本把回复、权限和失败收成三个总开关时，只把已保存的值迁移到对应的桌面通道。

## 3. 验收

- 通知是独立分类，常规页不再放这三项开关。
- 五类提醒的桌面和应用内可以分别开关，提示音和当前任务例外单独保存，重启后仍在。
- 窗口在后台只可能出桌面通知；窗口在前台只可能出应用内提醒。
- 正在查看的任务在前台保持安静，除非打开「正在查看的任务也通知」。
- 提问和批准请求的开关可以保存，没有可靠信号时不发出提醒。
