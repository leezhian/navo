# 集成设置

[设置概览](README.md) · [产品需求索引](../../../PRD.md) · [Issue 页面](../issues.md) · [任务工作台](../task-workspace.md)

## 1. 功能范围

- 支持 GitHub、GitLab、GitHub Enterprise、GitLab Self-Hosted 和 Linear 五个平台。前四个读取 Issue 和 PR（GitLab 的 MR 统一按 PR 展示），Linear 只读取 Issue，不出现在 PR 的列表、筛选和选择器里。
- 交互参考 Kepler 的 Settings → Integrations。区别是 Navo 没有自己的账号和服务器：授权页由各平台官方提供，授权结果只回到本机，不经过 Navo 的网站，也不同步到其他设备。换一台电脑要重新连接。
- Navo 本期只读取，不在平台上评论、改状态、建 PR 或写任何数据。不注册 webhook，不在后台推送通知。

## 2. 连接方式

- **一键连接（GitHub、GitLab.com、Linear）**：点「连接」后用系统浏览器打开该平台的官方授权页，授权完成自动回到 Navo，行内显示「已连接」。GitHub 使用 OAuth App：用户只需在官方页授权，无需安装应用。采用设备码方式：弹窗显示一次性验证码并打开 github.com/login/device，验证码可一键复制。设备码请求的权限为 `repo` 和 `read:user`。`repo` 是读取私有仓库 Issue／PR 的最小可用权限，但平台会一并授予写权限；授权弹窗须说明 Navo 只读取、不会写入。组织若开启了 OAuth 应用访问限制，需该组织管理员批准后才能读取该组织的条目。GitLab 与 Linear 采用浏览器授权并自动回调。
- 授权弹窗提供「复制授权链接」，浏览器没有自动打开时可手动打开；链接只能用一次，「重试」生成新链接。连接出现后弹窗自动关闭；「取消」放弃本次授权，不保存任何凭据。超时或被拒绝时说明原因并允许重试。
- **个人 token（GitHub Enterprise、GitLab Self-Hosted）**：点「连接」打开连接弹窗，填写服务器地址和个人访问令牌后「保存连接」。地址必须是 http 或 https，含端口和安装路径时一并填写，不能带用户名密码、查询参数或片段。弹窗说明需要的最小只读权限，并链接到该平台生成令牌的页面。
- 一键连接的三个平台在弹窗底部也提供「改用 token 连接」作为备用，GitHub、GitLab 用个人访问令牌，Linear 用 Personal API key。
- 保存前在本机向服务器校验 token，结果用以下文案之一：
  - 「凭据已通过服务器校验。」
  - 「凭据已保存，但无法验证服务器证书，请检查 TLS 配置。」
  - 「凭据已保存但未校验：无法连接服务器。」
  - 「服务器拒绝了这个 token，请检查它的值和权限。」（不保存）
- 校验通过后显示当前账号，并列出缺少的权限；缺少读取仓库或 Issue 的权限时保存但给出警告。信任操作系统证书库，公司自签 CA 无需额外配置。

## 3. 已连接状态与管理

- 每个平台一行：品牌图标、名称、状态（未连接／已连接／有警告），已连接时显示账号名和头像，自托管平台另显示服务器地址。
- 已连接行提供「重新连接」（自托管为「替换 token」）和「断开连接」。断开需二次确认，删除本机保存的凭据和该平台的缓存数据；平台支持撤销时同时撤销 token。已关联到任务的 PR/Issue 条目保留，只是不能再刷新。
- 警告与对应的唯一修复动作：
  - 「登录已过期」：能用刷新令牌续期时自动续期；续期失败提供「重新连接」。
  - 「无法连接服务器」：连接仍保留，提示检查网络或 VPN，恢复后自动消失，不建议重新连接。
  - 「无法读取返回内容」：可能有代理或网关拦截，提供「重试」。
  - 某个组织拒绝访问（如 GitHub 组织限制 OAuth 应用）：在行下标出该组织，只排除它的条目，其他条目照常读取。
- 分组顶部的「刷新」重新检查所有平台的连接状态。
- 本期每个平台只连接一个账号，自托管平台只连接一台服务器。

## 4. 凭据与隐私

- 凭据由主进程用系统钥匙串加密后保存在本机，渲染进程拿不到原文。不写入诊断日志、任务正文、启动 prompt、终端输出、Git 配置或远端 URL。
- 只请求读取所需的最小权限；平台的只读权限覆盖不了私有仓库时，按该平台的最小可用权限申请，并在弹窗说明 Navo 只读取。
- 从平台拉到的条目缓存在本机，用于离线展示和失败时保留上次结果。

## 5. 本期不做

- 自托管平台的一键授权、多账号和多服务器、「选择可见的组织／仓库」。
- Jira、Azure DevOps、Bitbucket 等其他平台。
- 任何写操作、webhook、后台通知、跨设备同步。

## 6. 验收标准

- 五个平台都能连接：GitHub 通过 OAuth App 设备码完成授权，用户只需授权、无需安装；GitLab.com 和 Linear 通过浏览器授权并自动回到 Navo；两个自托管平台通过地址加 token 连接；三个云平台都可改用 token 连接。
- GitHub 授权弹窗说明 `repo` 权限包含写入、但 Navo 只读取。
- 授权弹窗可复制链接、重试和取消；取消或拒绝授权不留下任何凭据；成功后弹窗自动关闭，行内显示账号。
- token 校验的四种结果文案准确；被拒绝时不保存，地址格式不合法时不允许保存。
- 断开连接需确认，确认后凭据和缓存从本机删除，已关联到任务的条目仍在。
- 凭据不出现在日志、prompt、终端、Git 配置和渲染进程里。
- 过期、无法连接、返回内容异常、组织拒绝访问四种警告分别显示对应的修复动作。
- Linear 不出现在任何 PR 相关的列表、筛选和选择器中。
