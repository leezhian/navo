# Agents 设置

[设置概览](README.md) · [产品需求索引](../../../PRD.md)

## 1. 范围

- 首版支持 Claude Code、Codex、Grok Build、Antigravity，仅使用本机 CLI，复用 CLI 默认账号。
- 不提供多账号、富聊天模式、ACP 自绘会话、外部会话检测、全局 hooks/MCP 安装或用量查询。
- 本页负责探测和管理 CLI；创建任务时的 Agent、模型、模式和思考等级选择见[创建任务](../task-create.md)。带配置任务保存后独立启动 CLI；任务会话、上下文交付和原生恢复边界见[任务工作台](../task-workspace.md)。

## 2. 页面与默认值

- 设置导航和页面标题统一为“Agents”，位于外观之后。顶部为默认 Agent，其下是 Agent 列表及“全部更新”“重新扫描”。
- 采用现有设置的独立圆角分组、缩进分割线、紧凑按钮，不照搬参考图的描边卡片或重复运行模式控件。
- 每组首行展示名称、已检测的版本或安装状态、安装/更新操作及启用开关；其下为账号和折叠的高级设置。不单独展示“安装”信息栏，可执行文件路径统一在高级设置中展示。未安装时不显示账号区域。
- 默认 Agent 从已安装且启用的条目中选择，也可不选择。默认项被禁用或路径失效时保留选择并提示重新选择，不自动替换；创建任务时据此预选，明确未安装或未登录时不可选择，未知状态允许继续查询。最终任务配置仍需真实能力验证通过，不因放宽状态筛选而填充预设模型。
- 启用开关不附加可见文案，保留无障碍名称；只控制后续可选范围，不卸载 CLI，不终止已有进程。更改失败保留上一份已保存配置并展示错误。

## 3. 本机检测与账号

- 进入页面和点击重新扫描时检测，期间保留已有结果；首次打开立即展示四个固定条目，未知版本和账号状态以中性占位显示，不用“正在检测”替换列表，也不提前判为未安装。切回页面先展示本次应用运行中的上次检测结果，再重新检测。检测独立于安装和登录，不在后台执行安装、更新或交互式登录。
- 先使用显式自定义路径，否则查找当前进程及登录 Shell 的 PATH，并补查常见安装目录。无效自定义路径显示检测失败，不悄悄执行其他文件。
- 可执行文件需为绝对路径、存在、具有执行权限且能成功输出版本。每次命令探测有超时，某个 Agent 失败不影响其他条目。
- Claude Code 使用官方认证状态命令，Codex 使用官方登录状态命令；旧版或无法识别的输出显示“登录状态未知”，不根据凭证文件存在推断已登录。
- Grok Build、Antigravity 首版不猜测登录状态。Grok 提供官方登录/退出命令；Antigravity 提供“在终端中管理”，由用户操作其交互界面。
- 仅在官方状态结果确实提供账号身份时显示；不复制 CLI 登录凭证，不要求 Navo 账号，不把身份或原始探测输出写入诊断日志。
- 模型、模式和思考等级按 Agent 与可执行文件路径保存在 SQLite；启动约 30 秒后、此后每 4 小时检查过期缓存。创建任务不触发检测。后台刷新或设置页扫描发现路径、版本、认证状态、可识别账号身份或支持的凭证文件元数据变化时重新查询；缓存只保存不可逆指纹，不保存账号身份和凭证明文。
- 修改路径、启用状态或认证环境，以及在 Navo 内完成安装、更新、登录、退出或终端管理操作后，立即使对应能力缓存失效并安排后台刷新。外部 CLI 变化在下一次后台检查或设置页扫描时发现；未提供稳定账号身份或凭证变更信号的 CLI（如当前 Antigravity），依靠 Navo 内操作失效及定期过期刷新，不宣称能即时识别外部账号切换。
- 刷新期间及失败时保留上次成功的能力数据；环境未变化时继续使用旧结果，已变化时旧结果仅供展示。相同 Agent 的并发探测合并，禁用项不进行后台能力探测。
- 登录和退出影响本机 CLI 默认账号，包括 Navo 以外的使用；执行前明确提示。

## 4. 安装、更新与操作面板

- 所有操作先显示实际命令，用户确认后才在内置终端执行。关闭确认面板不执行命令。
- macOS/Linux 的 Claude、Codex 在本机 npm 可用时提供官方 npm 包安装；Antigravity 提供官方安装脚本。Grok 未验证自动安装方式时提供官方说明。Windows 首版安装转到官方说明，不猜测命令。
- npm 更新固定到当前 CLI 的原安装前缀；支持的原生安装使用 CLI 自更新。应用捆绑、显式自定义路径及无法确认的包管理器安装不交给其他安装器覆盖，提供官方说明。
- 全部更新仅包含当前可更新项，确认全部命令后串行执行；一项失败不跳过后续项。展示每项执行结果，不能把进程仍在运行或退出失败当成成功。
- 操作执行期间不能通过遮罩、Esc 或关闭按钮误关闭；可明确“停止并取消剩余操作”。取消后不继续队列，不承诺回滚已经完成的安装或文件修改。
- 完成后保留终端输出供查看，关闭面板才释放；随后重新检测版本及登录状态。命令退出成功仅表示命令完成，登录状态仍以检测结果为准。
- 所有设置操作终端与创建窗口绑定，不是任务会话；关闭窗口或退出应用时终止其 PTY。终端输出只留在当前界面，不写入诊断日志。

## 5. 高级设置与保存

- 高级设置仅保留可执行文件路径，不提供启动参数和环境变量编辑入口。路径只读显示，可查看和复制，不能手动填写；自定义路径只能通过系统文件选择器指定。
- 选择文件后立即保存并重新检测，无需手动保存；取消选择或选择同一文件不重复提交，保存失败保留原路径并提示错误。
- 路径右侧依次为“重新扫描”按钮和文件系统图标。此处重新扫描会清除当前 Agent 的自定义路径覆盖，重新自动查找本机 CLI，并以检测结果更新路径；已处于自动模式时也重新检测。未找到时不继续展示旧自定义路径，按实际检测结果展示状态。顶部重新扫描仍保留各 Agent 的自定义路径。
- 路径、启用状态和默认项存入 SQLite；编辑路径和启用状态不改写其他已有配置。
- 不展示保存或恢复默认按钮；重新扫描不退出账号，不删除 CLI 全局配置。

## 6. 验收标准

- 只显示四种已确认的 Agent，无富聊天、多账号入口，中英文和浅深色均可用。
- 安装状态、版本、登录状态来自检测，未知状态不伪装为已登录或未登录。
- 首次检测不以加载文案替换卡片，重复扫描和切回页面保留已有内容；未返回检测结果时不展示未安装或未登录结论。
- 自定义路径和启用状态保存及重启恢复正确，保存失败不覆盖原值；高级设置中没有启动参数或环境变量控件。
- 默认项只接受可用且启用的 CLI，失效时有明确提示。
- 命令确认、窗口绑定、一次性启动、串行更新、失败和取消边界正确，不执行客户端提交的任意命令。
- 不修改任务状态、分支或 Worktree，不安装 hooks，不迁移用户登录凭证，不影响已有设置。
