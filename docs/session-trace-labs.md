# 实验室与会话轨迹接入方案

日期：2026-11-12。本文为架构设计依据；当前功能范围以 [实验室 PRD](prd/settings/labs.md) 与任务工作台 PRD 为准。独立包需单独发布到 Releases 后才可在线安装，本地校验安装不依赖发布。

本文描述最终目标结构、交互与技术边界。页面需求在功能落地时同步到 [设置](prd/settings/README.md)、[任务工作台](prd/task-workspace.md) 和 [产品索引](../PRD.md)。通用视觉遵循 [DESIGN.md](../DESIGN.md)。

## 1. 目标与范围

Navo 内置实验室管理与扩展加载能力，会话轨迹作为官方独立扩展安装。首次安装 Navo、已有用户升级时，轨迹均未安装、未启用。用户在实验室安装后再主动启用；关闭和卸载立即生效。

当前支持 Claude Code、Codex、Grok、Antigravity 已绑定到 Navo 的原生会话，提供终端与轨迹切换、轮次和模型请求分组、时间线、事件详情、搜索筛选、基础统计与实时追加。具体可展示内容以原生日志能够确认的信息为准；日志中没有的字段显示「未记录」，不补造。

首版不提供第三方插件市场、全机历史扫描、外部会话接管、运行对比、人工标注、自动异常分析或子 Agent 树。已有会话名称读取能力不代表日志一定可解析；无法定位日志目录或文件不可读时给出明确提示，不能停留在加载中。

参考 [Trace Review](https://github.com/Picrew/trace_view) 的轨迹展示与多来源适配思路。若复用其代码，需先核实具体版本的许可证和依赖，不直接把独立应用当作 Navo 插件运行。

## 2. 实验室入口与操作

设置增加「实验室」分类，位于「集成」与「关于」之间，参与设置分类搜索。会话轨迹条目展示用途、支持的 Agent、版本、安装大小和当前状态，沿用现有设置分组与控件风格。

| 状态 | 可用操作 | 工作台表现 |
| --- | --- | --- |
| 未安装 | 安装 | 保持现有终端界面 |
| 安装中 | 查看进度、取消 | 不展示轨迹入口 |
| 已安装、未启用 | 启用、检查更新、更新、卸载 | 不展示轨迹入口 |
| 已安装、已启用 | 关闭、检查更新、更新、卸载 | 支持的会话标题栏显示「终端 / 轨迹」图标切换 |
| 安装或运行异常 | 重试、查看原因；已安装时可卸载 | 保留终端能力 |
| 与 Navo 不兼容 | 安装兼容版本、卸载 | 不加载插件 |

- 安装：下载、校验、准备目录，成功后登记安装版本；安装完成仍保持关闭。
- 启用：注册轨迹入口，首次打开轨迹时才加载界面、读取会话记录。没有打开轨迹的会话不持续扫描。
- 关闭：立即撤销轨迹访问，取消读取和解析，释放监听、界面及插件进程。保留安装包和磁盘缓存。
- 卸载：先关闭，随后删除插件包、解析缓存和插件专属偏好。确认弹窗明确清理范围；失败保持关闭并展示残留清理状态，允许重试。
- 应用重启：恢复已保存的启用偏好，并重新核验安装完整性和兼容性，按需加载。

关闭与卸载不停止 Agent，不删除原生日志、Navo 任务、会话记录、仓库、Worktree 或代码文件。首版插件数据均可从原日志重建，不引入需要另行保留的人工标注。

## 3. 宿主与插件边界

| 部分 | 职责 | 随 Navo 安装 |
| --- | --- | --- |
| 实验室与扩展管理 | 官方扩展目录、安装记录、下载校验、启停卸载、兼容性检查 | 是 |
| 会话扩展容器 | 轨迹视图挂载点、当前会话标识、启停状态与受限查询通道 | 是 |
| 官方轨迹界面 | 事件列表、时间线、详情、搜索与筛选，使用项目统一组件和设计 token | 是，未安装或未启用时不展示、不加载 |
| 会话轨迹插件 | 日志定位与解析适配、搜索、统计、增量处理及查询接口 | 否，独立分发 |

Navo 正式安装产物不包含轨迹解析器，也不预埋插件压缩包；官方轨迹界面随 Navo 发版，界面变更跟随 Navo 版本，不随插件包热更新。扩展在同一代码仓库开发时必须使用独立构建入口，并检查最终安装产物的边界。

建议的插件包结构：

```text
session-trace/
├── manifest.json
└── runtime/
```

清单记录稳定插件 ID、插件版本、宿主接口版本 `apiVersion`、兼容的 Navo 版本、解析入口及所需能力。首版用 `apiVersion` 兼任轨迹查询协议版本，当前值为 1；查询协议不兼容时递增 `apiVersion`，按不兼容处理，提示更新插件或 Navo，不渲染半套结果。首版仅接受官方目录中登记的扩展，不提供任意地址和任意脚本执行入口。

官方插件的界面不使用 iframe，由宿主直接渲染在会话面板的轨迹视图中，复用项目现有的输入框、分段按钮、提示和设计 token，与任务工作台保持一致（参考 DeepSeek Harness 官方插件通过类型化挂载点向宿主贡献界面的做法）。宿主界面只通过受限查询通道向插件进程取数据，查询校验会话范围、查询类型和当前插件状态，不转发任意 IPC 或文件路径。隔离 iframe 仅保留给未来的第三方插件界面，首版不开放。

解析运行在 Electron 独立辅助进程中，避免大日志解析阻塞主进程。辅助进程用于故障与资源隔离，不等同于可执行不可信第三方代码的安全沙箱。关闭、卸载和应用退出时终止其工作并释放资源。

## 4. 分发、安装与持久化

插件通过 `leezhian/navo` 的 GitHub Releases 单独分发，无需额外插件服务。安装包需要验证发布来源、文件完整性、入口路径及兼容性；不能仅使用同来源的未认证哈希作为可信来源证明。解包限制大小和路径范围，拒绝目录穿越及越界链接。

官方版本通过 GitHub Releases 的固定签名清单分发；宿主内置 Ed25519 公钥，先验签再选择接口与宿主主版本兼容的稳定版本。已安装插件后台只检查版本元数据；用户点击更新后才下载，不自动安装或降级。通过更新清单安装的版本保存签名凭证，内置基线按固定摘要校验，断网重启仍可验证。

下载先进入临时目录，校验成功后切换到正式版本目录，再更新安装记录。更新先保存包含旧版本与启用偏好的操作记录，旧目录保留为备份直到数据库提交成功；失败和崩溃回退旧版，成功后恢复原启用状态并清理备份。安装取消或失败清理本次临时内容；应用异常退出后核对未完成操作，不把半成品标为已安装。文件系统变更与数据库记录之间使用操作记录协调，不能依赖 SQLite 事务回滚文件删除或移动。

同一个插件的安装、启用、关闭、卸载串行执行，重复请求幂等处理。关闭先撤销访问和订阅，再停止运行实例，丢弃旧实例迟到的结果。目录清理完成前不显示卸载成功。

安装状态、用户启用偏好、当前运行状态和进行中的操作分别表达，避免一个布尔值同时代表「已经下载」「允许使用」和「运行正常」。运行失败需明确展示，不将已安装误报成可用。

- Navo 的 SQLite 保存插件安装版本、启用偏好和必要操作记录。
- 插件包和缓存位于 Navo 用户数据目录下的专属目录，开发与正式环境继续隔离。
- 插件缓存与任务业务表分离，保存可重建索引和解析结果，设置容量与淘汰策略。
- 卸载清除插件专属数据，保留宿主内置的官方目录条目，以便重新安装。
- Navo 升级后重新检查插件兼容性；不兼容时阻止加载并提供明确处理入口。

## 5. 会话数据与解析

现有 `TaskSession` 提供 `nativeSessionId`、`nativeHistoryRoot`、`cwd` 与 Agent 标识，可复用原生身份绑定规则。前端提交 Navo 会话 ID，由主进程核对所属任务和原生来源，插件只获得当前会话所需的只读历史访问。

```mermaid
flowchart LR
  A[当前 Navo 会话] --> B[核对原生 ID 与历史来源]
  B --> C[只读加载对应日志]
  C --> D[插件适配器解析]
  D --> E[统一轨迹事件]
  E --> F[时间线与事件详情]
  C --> G[可见时监听新增内容]
  G --> D
```

不按最近修改时间猜测会话，不默认扫描全部用户历史。原生 ID 尚未绑定、无法定位日志目录、记录不存在、文件不可读、格式不支持分别显示对应状态，不用空结果冒充成功，也不能停留在加载中。

各 Agent 只读取已绑定会话对应的日志：

- Claude Code、Codex 沿用现有绑定路径。
- Antigravity 读取 `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript_full.jsonl`。每条有 `created_at` 和递增的 `step_index`；工具调用没有 id，按出现顺序与紧随其后的结果配对。`status` 为 ERROR 时只记一条错误（优先使用 error 字段，没有则记该条的第一条可见内容），同条里的思考和回复仍按原类型展示，不重复计入错误数；工具结果失败只标该条结果。
- Grok 正文读取 `~/.grok/sessions/<cwd>/<id>/chat_history.jsonl`，时间与耗时先从同目录 `events.jsonl` 按 `tool_call_id` 和轮次起止补全，仍缺的再用同目录 `updates.jsonl` 中能按消息精确对应的时间补全；对不上的保持无时间，不按顺序或相邻记录推测。`events.jsonl` 仅较新版本才会完整写入，老会话可能只有部分轮次有时间。`chat_history.jsonl` 以整文件替换而非追加，文件被替换后必须重建索引，不能按偏移追加。

适配器统一输出用户消息、助手消息、日志中可见的推理、系统与上下文、工具调用与结果、错误、上下文压缩和未知事件。保留稳定事件 ID、轮次、可确认的请求标识、工具调用 ID（没有 id 时按顺序配对）、来源位置与时间信息。

- 工具调用和返回结果优先按调用 ID 关联，处理跨行与异步返回；日志没有调用 ID 时（如 Antigravity）按出现顺序与紧随的结果配对。
- 流式事件与最终响应去重。
- 用户轮次与模型请求分开，单轮可包含多次模型请求。
- 自动注入的上下文只根据可靠的原生标记识别，不能把现有规则文件反填成过去实际发送的内容。
- 缺少耗时、请求边界时保留缺失，界面显示「未记录」，不写成 0，也不因此隐藏该行；可推导的估算值明确标注。轨迹视图不显示会话总时长，时间线不显示时间刻度、轴两端的起止时间，也不保留给刻度对齐的浅色竖线，不读取、不统计 Token 用量（包括 Grok 的 `usage.json`）。时间线只绘制有时间的事件。
- 没有时间戳的事件只进入列表，不进入时间线，也不作为框选依据、不计入选区命中；框选生效时这些列表行按选区外置灰。整段会话都没有时间时，隐藏时间线并提示「该会话未记录时间，无法使用时间线和框选」，列表仍全部展示；只有部分事件有时间时，时间线只绘制这些事件，不另做空状态。
- 不可识别事件保留原始记录访问，原始 JSON 按需加载。
- 不从终端画面反推轨迹，不向 CLI 写入采集 hooks，不新增采集用的用户输入。

初次读取从头分块解析并建立完整索引（轮次与工具调用配对依赖前文状态），之后按滚动窗口分段查询、正文按需读取；界面用虚拟列表展示全部匹配结果，不提供翻页，首次打开停在最新事件，往上滚动再取更早的窗口。增量读取记录文件身份和偏移，处理尾行尚未写完、截断、轮转和替换；追加型日志只追加新内容，整文件替换的日志（如 Grok 的 `chat_history.jsonl`）在被替换后重建索引。缓存键包含原生会话身份、源记录信息和解析器版本，版本或来源变化时重建。统计基于完整索引，时间线只包含有时间戳的事件。

同一会话的多个可见视图共享解析和监听。会话面板内终端↔轨迹切换保持解析进程；关闭会话面板、隐藏任务、关闭插件或切换会话后释放监听，再次打开时校验缓存并补读。关闭插件终止全部订阅，源文件被删除时取消对应读取，不静默切换到其他历史。

日志内容作为不可信数据展示，Markdown、链接和 JSON 不执行其中脚本或命令。会话正文、工具参数、代码与凭据不写入 Navo 诊断日志，轨迹内容不上传。

## 6. 工作台集成与会话生命周期

会话面板启用轨迹后在标题栏右侧提供「终端 / 轨迹」图标切换（当前项高亮、悬停显示名称，不另起一行 tab），首版默认仍进入终端。轨迹包括紧凑统计（轮次、请求、工具、错误）、输入/模型/工具时间线、类型筛选、全文搜索、按轮次和请求分组的事件列表，以及右侧事件详情。详情支持参数、结果、日志中的文件修改和原始 JSON；统一在右侧面板打开，列表行不再展开；未选中时不展示详情栏，再次点击当前选中事件则收起。列表与详情之间可沿分割线拖动调整宽度，拖动热区不单独占一列。

切换到轨迹时保留原有 PTY 和终端状态，正在运行的 Agent 继续执行。停止的会话仍可读取历史，不依赖终端缓冲存在。

当前 `useVisibleSessionResume` 按 Agent 面板可见性尝试恢复会话。接入后必须同时检查「终端视图真正可见」，查看轨迹不会启动 CLI。关闭或卸载插件导致的自动回退也不触发恢复，须区分用户主动打开终端与功能关闭造成的视图变化。

归档会话的历史查看不隐式解除归档或恢复进程；如提供该入口，应与已有归档恢复操作分开。插件关闭后取消其视图选择和监听，不修改任务、Agent 状态或原生会话绑定。

## 7. 接入位置与文档同步

职责延续现有目录，不把安装器、解析器或日志副作用塞进页面组件。

| 接入位置 | 目标职责 |
| --- | --- |
| `src/components/settings` | 实验室分类、扩展条目与操作反馈 |
| `src/components/tasks/workspace` | 会话视图切换、扩展容器与官方轨迹界面 |
| `src/hooks`、`src/services` | 界面状态、订阅生命周期与受限 IPC 封装 |
| `src/shared`、`src/preload.ts` | 安装状态、消息契约、受限扩展 API |
| `src/main-process` | 安装管理、运行实例、受控历史读取、持久化与退出清理 |
| 独立插件构建目录 | Agent 适配器、解析、索引与查询接口 |

对应产品规则维护在以下文档：

- 新增 `docs/prd/settings/labs.md`，定义实验室展示与生命周期规则。
- 更新设置概览分类、搜索和状态验收。
- 更新任务工作台的轨迹入口、历史读取与自动恢复边界。
- 更新 `PRD.md` 索引及非目标描述，允许主动安装启用后的原生日志只读能力，继续禁止 hooks 注入。
- 更新 `README.md` 的插件构建分发、目录与验证说明。页面专属规则不写入 `DESIGN.md`。

## 8. 验收与实施前核对

1. 新安装和升级均默认未安装、未启用；正式安装包不包含轨迹解析器与插件包；轨迹界面未安装或未启用时不展示、不加载。未安装或关闭时，没有插件进程和轨迹文件监听。
2. 安装成功、取消、断网、校验失败、目录无权限、应用中断等状态可正确恢复；不出现半安装和假成功。
3. 启用、关闭、卸载及重复操作结果一致；卸载期间正在解析的任务停止，晚到结果不再进入界面。
4. 关闭、卸载、运行崩溃不影响现有终端，不损伤任务、原生日志与工作目录；查看历史和自动回退不启动 Agent。
5. Claude Code、Codex、Grok、Antigravity 均使用基于真实样例脱敏的隔离日志夹具，覆盖解析、索引、事件关联、去重、统计、缺失字段、空行与坏行、未知格式、追加、截断、轮转与整文件替换，不调用真实模型做测试。
6. 大日志按需读取，多视图共享监听；页面隐藏、插件关闭、任务/会话删除及应用退出后资源释放。
7. 界面支持项目现有两种语言、浅深色与窄窗口，搜索无结果、无法定位日志目录、历史缺失和解析失败有明确区分，不能停留在加载中；搜索框、筛选和提示使用项目统一组件，不另写一套样式。新增事件类型接入类型颜色与描边，用户可见文案走 i18n。
8. 校验权限边界、消息来源、包路径与缓存隔离；发布构建验证辅助进程、插件包加载和 Electron 打包配置的兼容性。

实现前需确定官方发布仓库、发布清单的验证方式、宿主接口版本规则及首版支持的日志格式范围。先用最小安装包在正式打包环境验证加载与完整卸载；新增依赖按项目规则单独确认。
