# Vibe Reviewer 设计规格

## 背景

Vibe Reviewer 是基于 Tauri 2、React、Vite 和 TypeScript 的桌面应用。`vibe reviewer.md` 中的 PRD 描述了一个本地代码审查工具：监听 AI Agent 会话结束，检测 Git 改动，并在提交前以接近 GitHub PR 的方式展示 diff。

当前项目仍接近 Tauri 初始模板。未经用户确认，不新增 npm 依赖或其他依赖包。

## 已确认方向

视觉方向采用 A1：平衡型 macOS 桌面审查工具。

界面由以下部分组成：

- Finder 风格左侧会话栏。
- 右侧审查工作区，包含两行顶部通栏。
- GitHub 风格 diff 阅读区。
- 参考用户截图的右侧强文件树。
- 自定义 macOS 桌面设计系统，不使用远方好物 B 端规范。

## MVP 范围

实现应覆盖 `vibe reviewer.md` 的 MVP：

- Claude Code、Codex、OpenCode、Qoder 的监听配置。
- 会话列表展示 Agent、项目、分支、文件数、增删行、更新时间、未读状态。
- 点击会话打开审查区。
- 对比方式：未暂存、已暂存、分支、上轮对话。
- Git diff 展示。
- 文件树导航。
- 统一视图和分栏视图切换。
- 差异换行切换。
- 折叠/展开全部。
- 刷新 diff。
- 外观设置：跟随系统、浅色、深色。
- 设置和会话记录本地持久化。

如果真实 Agent 事件集成路径暂不明确，可以先提供本地模拟或手动检测路径，但监听边界需要明确，方便后续接入真实 Agent。

## 布局

### 会话列表

会话列表是启动后的主视图。每个会话展示：

- Agent 标签。
- 项目名。
- 分支名。
- 文件数量。
- 新增和删除行数。
- 最近更新时间。
- 未读红点。

空状态需要说明如何开启监听，并提供进入设置的入口。

### 审查工作区

选中会话后展示：

- 左侧会话侧栏。
- 右侧审查工作区。
- 审查区可关闭。

审查区包含：

- 第一行通栏：对比方式、增加行、删除行、文件数、查看选项、统一/分栏切换、刷新。
- 第二行通栏：当前分支和目标分支，或 session baseline。
- 主体左侧：diff 阅读区。
- 主体右侧：可筛选的文件树。

## Diff 阅读模型

默认阅读模式是“全文件连续模式”。这符合 PRD 和 GitHub PR 的阅读预期。

当 diff 超过大差异阈值时，应用自动切换到“单文件模式”并展示提示。用户可以手动切回连续模式。

建议阈值：

- 单文件 diff 超过 3000 行。
- 或总 diff 超过实现时定义的高阈值。

差异视图支持：

- 统一视图：增删行在同一代码流中。
- 分栏视图：旧代码与新代码左右分栏。

视图切换在顶部工具栏中通过一个按钮完成，并持久化到本地设置。查看选项按钮负责打开菜单，菜单内包含差异换行和折叠/展开全部。

## 数据流

前端状态拆为：

- 设置状态：启用的 Agent、主题、diff 偏好、最近目标分支。
- 会话状态：本地会话记录、当前选中会话、未读状态。
- 审查状态：对比方式、diff 加载/错误、当前文件、阅读模式、折叠文件。

Tauri command 负责文件系统和 Git 操作：

- 读写本地应用数据。
- 执行 Git status 和 diff。
- 列出分支并解析默认目标分支。
- 在具备快照时加载上轮对话基线。

Git diff 需要解析为结构化数据后再进入渲染层，避免 UI 直接依赖原始字符串。

## 异常处理

界面必须局部展示错误，不能让整个工作区崩溃：

- 非 Git 目录：不生成审查任务，并在监听状态记录原因。
- Git 命令失败：审查区显示错误和重试按钮。
- 项目路径丢失：历史会话保留，并允许移除。
- 缺少上轮对话基线：禁用上轮对话模式并说明原因。
- 二进制文件：展示文件状态和占位，不展示代码行。
- 大文件：默认折叠，允许手动展开。

## 代码组织

代码目录按职责拆分：

- `src/domain`：领域类型、diff 解析、文件树模型、mock 数据。
- `src/services`：Tauri API 与数据访问。
- `src/hooks`：复用状态逻辑。
- `src/components/layout`：mac 窗口和布局。
- `src/components/session`：会话列表。
- `src/components/review`：审查工具栏、diff、文件树、状态块。
- `src/components/settings`：设置页。
- `src/utils`：纯工具函数。

`App.tsx` 只做状态编排，避免成长为超长组件文件。

## 验证策略

当前没有测试框架，暂不新增测试依赖。实现中优先将解析和状态逻辑写成纯函数，至少通过 TypeScript 和构建验证。

验证命令：

- `pnpm build`
- 如涉及 Rust 改动，通过 Tauri 构建链路验证。
- 对主要 UI 状态进行浏览器或应用截图检查。

## 待后续确认

Agent 事件检测是主要未知点。首版先建立监听配置和集成边界，并用本地可验证行为支撑 UI 和 Git 审查流程。

上轮对话快照必须本地保存、默认私有。首版可以先使用快照元信息和 Git 兼容基线，真实监听路径确认后再完善存储策略。
